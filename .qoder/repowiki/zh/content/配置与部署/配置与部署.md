## 配置文件详解

DeerFlow 的核心配置通过 `conf.yaml` 文件进行管理，该文件定义了 LLM 提供商设置、智能体行为参数、搜索工具集成等关键配置项。配置文件采用 YAML 格式，支持环境变量注入和灵活的模块化配置。

### LLM 提供商配置

`conf.yaml` 文件中的 `BASIC_MODEL` 部分定义了基础语言模型的连接参数：

- **base_url**: LLM 服务的 API 端点地址，例如 `http://192.168.0.106:8088/v1`
- **model**: 使用的模型名称，例如 `qwen3-0.6`
- **api_key**: 认证密钥，用于访问 LLM 服务
- **verify_ssl**: 布尔值，设置为 `false` 可禁用 SSL 证书验证（适用于自签名证书场景）

此外，支持 Google AI Studio 等其他平台的配置，通过 `platform` 字段指定平台类型，并使用相应的 API 密钥。

可选的 `REASONING_MODEL` 配置允许为规划任务指定专用的推理模型，提升复杂任务的处理能力。

### 智能体配置

智能体的行为由 `src/config/configuration.py` 中的 `Configuration` 类定义，主要参数包括：

- **max_plan_iterations**: 最大计划迭代次数，默认为 1
- **max_step_num**: 单个计划中的最大步骤数，默认为 3
- **max_search_results**: 搜索结果的最大数量，默认为 3
- **search_engine**: 指定使用的搜索引擎，如 `tavily`
- **report_style**: 报告生成风格，支持学术型（ACADEMIC）等样式
- **enable_deep_thinking**: 是否启用深度思考模式

这些参数可通过环境变量或运行时配置进行覆盖，实现灵活的运行时调整。

### 工具集成选项

DeerFlow 支持多种搜索工具的集成配置：

#### Tavily 搜索引擎

`SEARCH_ENGINE` 配置允许通过域名白名单和黑名单精细控制搜索范围：

- **include_domains**: 仅包含来自指定域名的结果（如 `gov.cn`, `edu.cn`）
- **exclude_domains**: 排除来自指定域名的结果

#### 自定义搜索仓库

`CUSTOM_SEARCH` 配置支持多个自定义搜索仓库的定义，每个仓库包含：

- **name**: 仓库名称（如 "聚合搜索"）
- **description**: 描述信息
- **repository**: 仓库标识符
- **channel_id**: 通道 ID

通过 `default_repository` 字段指定默认使用的搜索仓库。

## 环境变量管理

DeerFlow 通过 `src/config/loader.py` 模块实现了强大的环境变量管理功能，支持在配置文件中使用 `$VAR_NAME` 语法引用环境变量。

### 环境变量处理机制

`loader.py` 提供了以下核心功能：

- **replace_env_vars**: 递归替换配置中的环境变量引用
- **process_dict**: 处理字典结构，支持嵌套的环境变量替换
- **load_yaml_config**: 加载 YAML 配置文件并应用环境变量替换，结果缓存以提高性能

### 配置优先级

配置值的优先级顺序为：环境变量 > 运行时配置 > 配置文件默认值。这种设计允许通过环境变量轻松覆盖默认配置，特别适合容器化部署场景。

### 前端环境变量

前端应用通过 `web/src/env.js` 定义环境变量模式，使用 `@t3-oss/env-nextjs` 进行类型安全的环境变量管理：

- **NEXT_PUBLIC_API_URL**: 指定后端 API 地址
- **NEXT_PUBLIC_STATIC_WEBSITE_ONLY**: 启用静态网站模式
- **NODE_ENV**: 指定运行环境（development/test/production）

## 容器化部署流程

DeerFlow 提供了完整的 Docker 和 docker-compose 部署方案，支持前后端分离的容器化部署。

### Docker 镜像构建

`Dockerfile` 使用 `uv` 作为 Python 包管理器，基于 `ghcr.io/astral-sh/uv:python3.12-bookworm` 基础镜像：

1. 安装系统依赖（如 `libpq-dev`）
2. 预缓存应用依赖以加速构建
3. 复制应用代码到容器
4. 暴露 8000 端口
5. 使用 `uv run` 启动服务器

构建命令：
```bash
docker build -t deer-flow-backend .
```

### Docker Compose 部署

`docker-compose.yml` 定义了前后端服务的编排：

- **backend 服务**: 构建后端镜像，从 `.env` 文件加载环境变量，将 `conf.yaml` 挂载为只读卷
- **frontend 服务**: 构建前端镜像，暴露 3000 端口，依赖后端服务

部署命令：
```bash
docker-compose up -d
```

该配置实现了服务间的网络隔离和依赖管理，确保稳定运行。

## 初始化脚本与便捷命令

## 生产环境最佳实践

### 性能调优

1. **依赖预缓存**: 利用 Docker 构建阶段的依赖缓存，减少构建时间
2. **连接池**: 在 `pyproject.toml` 中声明 `psycopg[binary]` 依赖，优化数据库连接性能
3. **配置缓存**: `load_yaml_config` 的内置缓存机制减少重复文件读取开销

### 日志管理

1. 使用标准的 `logging` 模块，通过 `logger.info()` 和 `logger.warning()` 记录关键信息
2. 在生产环境中设置适当的日志级别，避免过度日志输出
3. 将日志输出重定向到集中式日志系统

### 监控设置

1. 通过 `NEXT_PUBLIC_API_URL` 环境变量集成 Amplitude 等分析工具
2. 使用 `uvicorn` 的内置监控功能
3. 实现健康检查端点以支持容器编排系统的存活探针

## 故障排除指南

### 依赖冲突

**问题**: Python 包版本冲突  
**解决方案**: 使用 `uv sync --locked` 确保依赖版本与 `uv.lock` 文件一致

### 端口占用

**问题**: 3000 或 8000 端口被占用  
**解决方案**: 
1. 检查端口使用情况：`lsof -i :3000`
2. 修改 `docker-compose.yml` 中的端口映射
3. 终止占用进程或使用其他端口

### 配置错误

**问题**: 配置文件加载失败或环境变量未生效  
**解决方案**:
1. 确认 `conf.yaml` 文件路径正确挂载到容器
2. 检查环境变量名称是否与配置文件中的 `$VAR_NAME` 匹配
3. 验证 YAML 文件格式正确性
4. 查看日志中的配置加载信息

**问题**: SSL 证书验证失败  
**解决方案**: 在 `conf.yaml` 中设置 `verify_ssl: false`

**问题**: 自定义搜索仓库无法访问  
**解决方案**: 
1. 确认 `default_repository` 名称与 `repositories` 中的定义完全匹配
2. 检查网络连接和认证信息
